- **One fingerprint for a key and its Card (Coach).** `connect-an-app@10` and `draft-the-card@8`: for an app connected by key, the request carries the taf's tools (a reviewed entry's come with it), and the connection server declares them at once. Once it says they're declared, Coach agrees the rules, drafts the Card and shows one approval, so the key sheet signs the key and the Card together. The sheet is the ask: there's no separate "may I connect?" card for a key. A grant that isn't declared goes key first, then Card, as before (docs/secure-connection.md).
- **An app from search is asked for with only the tools the taf uses (Coach).** `connect-an-app@10` sends `uses` again for every entry, so a managed app's sign-in and a reviewed key entry both ask the owner for those tools alone. `@9` had dropped it for every entry because a reviewed key entry refused it.
