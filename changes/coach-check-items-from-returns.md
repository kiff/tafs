- **Coach takes a check's list from the read's returns** (set-up-a-taf@11, the-dial@6). A schedule's check names where its read's list is (`items`) by the path the tool's catalog `returns` gives (such as `data.messages`), never a guess: Gmail's first check failed on a guessed path ("the check's read has no …").
- **Coach names an operation's fields as its server gives them** (name-the-tools@11), never from the vendor's API it knows: a one-payment read named Stripe's `charge` where the server's details said `id`, so the taf couldn't read the payment and never refunded it.
- **Coach no longer tells the owner its own procedure** (draft-the-card@16): when a connection's tools are declared, it sends the Card in the same approval without saying so ("Declared, so the Card can go in the same approval." reached the owner).
