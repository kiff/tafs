- **Chrome 0.2.14: a taf works on the page you're on.** A message to a taf from the side panel carries the page in front, as Coach's does (with your page consent, only on that taf's sites, masked), and a taf never sends your own tab to another address: anything else it opens goes to a tab of its own. A newer run of a taf ends an older one you paused, so one taf never shows two runs at once ([docs/chrome.md](../docs/chrome.md), "A taf works where you are").

- **A taf reads the page you're on, on its own sites** (Chrome 0.2.14). A message you send a taf from the Chrome side panel carries the page in front, as a message to Coach does, under the same page consent, now version "2" so everyone is asked again. tafs cloud gives the taf the page only when its host is one of the sites you signed for that taf on your phone, checked against planque's list as well as in the extension. Any other page, a taf signed for any public site, or one with no browser connection is refused, and nothing starts. With a page in front the taf only reads (`browse_open`, `browse_read`), and what's kept is the site's name, never the page. Every taf's shared instructions and `a-browser-taf@7` say "this page" is the page you sent, read where it is, never a search or a start page.
